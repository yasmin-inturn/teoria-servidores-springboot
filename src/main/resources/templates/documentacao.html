Secao 2

Como a requisicao atravessa o servidor

O caminho de um POST /api/pedidos com JSON, da porta TCP ate o commit no banco. Cada etapa e uma peca que da para inspecionar no codigo deste projeto.

  1. Tomcat embarcado aceita a conexao

    O main() subiu um Tomcat dentro do processo. Ele tira uma thread do pool para esta requisicao, interpreta a linha de status e os cabecalhos HTTP e entrega um objeto HttpServletRequest.

  2. Cadeia de filtros do Spring Security

    Antes de qualquer codigo de negocio: o filtro do resource server le Authorization: Bearer ..., confere a assinatura HMAC e a expiracao do JWT e guarda a identidade no SecurityContext. Token invalido para aqui, com 401.

  3. DispatcherServlet escolhe o metodo

    O servlet central consulta o RequestMappingHandlerMapping - a mesma estrutura que a tabela abaixo esta lendo - e descobre que POST /api/pedidos pertence a PedidoController.criar.

  4. Jackson desserializa, Bean Validation valida

    O JSON vira um PedidoRequest (um record). As anotacoes @NotEmpty, @Min e @Pattern rodam antes do corpo do metodo: dado invalido virou HTTP 400 com a lista de campos, sem tocar no banco.

  5. A transacao abre no proxy do servico

    O PedidoService injetado no controller nao e a classe original, e um proxy. Ele abre a transacao, chama o metodo real e decide no fim: commit se retornou, rollback se escapou uma RuntimeException.

  6. Regras de negocio, na ordem

    Baixa de estoque item a item (EstoqueService, que exige transacao ativa), desconto (DescontoService), frete por regiao de CEP (FreteService) e pagamento (PagamentoService). Cartao recusado lanca excecao - e tudo o que veio antes e desfeito.

  7. Hibernate traduz objetos em SQL

    O pedido, os itens e o pagamento sao gravados em cascata. O estoque nem precisa de UPDATE explicito: a entidade esta gerenciada e o dirty checking gera o SQL no flush.

  8. Commit e resposta

    Com o commit feito, o controller devolve 201 Created, o cabecalho Location do novo pedido e o JSON serializado pelo Jackson. A thread volta para o pool.

Experimentos para rodar durante a apresentacao

curl 
# 1. catalogo e publico
curl -s http://localhost:8080/api/produtos

# 2. login (devolve o JWT)
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"cliente@loja.com","senha":"cliente12345"}' | sed -E 's/.*"token":"([^"]+)".*/\1/')

# 3. pedido que da certo: estoque baixa, pagamento PIX autorizado, status PAGO
curl -s -X POST http://localhost:8080/api/pedidos \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"itens":[{"sku":"TEC-MEC-01","quantidade":2}],
       "cepEntrega":"01310-100","metodoPagamento":"PIX","cupom":"PRIMEIRACOMPRA"}'

# 4. estoque insuficiente: 409 e NADA e gravado (WEB-FHD-03 tem 1 unidade)
curl -s -X POST http://localhost:8080/api/pedidos \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"itens":[{"sku":"WEB-FHD-03","quantidade":5}],
       "cepEntrega":"01310-100","metodoPagamento":"PIX"}'

# 5. pagamento recusado: cartao terminado em 0000 derruba a transacao inteira.
#    Confira /api/produtos depois: o estoque voltou ao que era.
curl -s -X POST http://localhost:8080/api/pedidos \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"itens":[{"sku":"SSD-1TB-NV","quantidade":1}],"cepEntrega":"69900-000",
       "metodoPagamento":"CARTAO_CREDITO","numeroCartao":"4111111111110000"}'

# 6. rota de admin com token de cliente: 403
curl -s -o /dev/null -w '%{http_code}\n' -X DELETE http://localhost:8080/api/produtos/1 \
  -H "Authorization: Bearer $TOKEN"

# 7. saude do servico, do jeito que o Kubernetes pergunta
curl -s http://localhost:8080/actuator/health
Secao 3

O codigo do servidor

O codigo abaixo e o deste servidor, lido do proprio classpath em tempo de execucao pelo CodigoFonteService. O maven-resources-plugin copia src/main/java para dentro do artefato durante o build, entao a pagina mostra o fonte real tambem quando roda como java -jar.

Comando que subiu este servidor ./mvnw spring-boot:run

Alternativa empacotada (gera o jar autossuficiente com o Tomcat dentro): ./mvnw clean package && java -jar target/*.jar. Nenhum servidor externo precisa ser instalado; o build baixa o proprio Maven pelo wrapper (mvnw), entao a maquina so precisa de um JDK 25.
